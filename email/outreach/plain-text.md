# Plain-text versions

Two uses:

1. **The multipart alternative.** Mailchimp auto-generates one from the HTML and it comes out
   badly — it flattens the module cards into orphaned fragments. Paste these over it.
2. **The control arm.** Send this from a person's own address, no template, and test it against
   the designed HTML. On reply-goal B2B outreach, plain text usually wins.

**No merge tags.** What you read below is what every recipient receives, word for word. The only
tags are the four Mailchimp system tags in the footer (`*|UNSUB|*`, `*|LIST:ADDRESS|*`, and
friends) — legally required, resolved automatically on send, nothing to configure. Sending from
somewhere other than Mailchimp? Replace those two lines with a real opt-out and your postal
address.

## One difference from the HTML

The HTML splits these same sentences across a hero, a card row, and a coloured block, so a few
lines appear in a different order and one lead-in is phrased for the cards ("Here's what you'd
get:"). Above, everything runs as continuous prose. The words are the copy library's Version A
text with the variable tokens resolved — see README.md for the exact list of what changed.
